  <files>apps/game/src/render/terrain/terrainChunkManager.ts</files>
  <action>
Replace the entire `createTerrainMaterial` function in `terrainChunkManager.ts` with a new desert-themed approach. Also add vertex displacement to terrain chunks for gentle hills.

**Replace `createTerrainMaterial`:**
The old function draws grid lines and green rectangles. Replace it completely with a desert material:
- Create a StandardMaterial with desert base colors: diffuseColor(0.82, 0.72, 0.55), specularColor(0.04, 0.04, 0.03), no emissive
- Do NOT create a shared DynamicTexture (this causes tiling). Instead, the material just has a base sand color. Per-vertex color variation will handle visual interest (added via vertex displacement below).
- Remove the `uScale`/`vScale` texture scaling since we're not using a tiled texture

**Add terrain height function (module-level):**
Create a `terrainHeight(worldX: number, worldZ: number)` function using multi-octave value noise:
- 3 octaves of value noise
- Base amplitude: 8 meters (gentle hills -- keeps flat physics colliders usable)
- Base frequency: 0.002 (wavelength ~500m for large rolling hills)
- Each octave: amplitude *= 0.45, frequency *= 2.1
- Use a hash function for noise corners: `hashNoise(x, z) = (((x * 73856093) ^ (z * 19349663) ^ 48291) >>> 0) % 65536 / 65536`
- Bilinear interpolation with smoothstep between corners
- Export this function so other systems could use it later if needed

**Add vertex displacement to chunk creation in `refreshVisibleChunks`:**
After `MeshBuilder.CreateGround(...)` creates the mesh, before `freezeWorldMatrix()`:
1. Get vertex positions: `mesh.getVerticesData(VertexBuffer.PositionKind)`
2. For each vertex (stride 3: x at i, y at i+1, z at i+2):
   - Compute world position: `worldX = positions[i] + center.x`, `worldZ = positions[i+2] + center.z`
   - Set `positions[i+1] = terrainHeight(worldX, worldZ)`
3. Update vertices: `mesh.updateVerticesData(VertexBuffer.PositionKind, positions)`
4. Also add per-vertex colors for visual variation to avoid tiling:
   - Create a Float32Array for vertex colors (4 floats per vertex: RGBA)
   - For each vertex, compute a sand color with noise variation:
     - Base: R=0.82, G=0.72, B=0.55
     - Add noise based on world position (use a different hash from the height noise): vary each channel by +/- 0.06
     - Occasionally (hash check < 0.05) make vertices darker (rocky patches): R=0.59, G=0.51, B=0.39 with slight noise
     - A=1.0 always
   - Apply: `mesh.setVerticesData(VertexBuffer.ColorKind, vertexColors)`
5. Recalculate normals: `mesh.createNormals(true)` -- critical for proper lighting on hills
6. Set the material to use vertex colors: on the shared material, set `material.diffuseColor = Color3.White()` so vertex colors are the actual diffuse color (Babylon.js multiplies vertex color with material diffuse). Actually, better approach: create the material with `useVertexColors = true` (this is not a property -- instead Babylon.js automatically uses vertex colors when they exist on the mesh and the material doesn't override them). The simplest approach: set `material.diffuseColor = new Color3(1, 1, 1)` (white) so vertex colors show through unmodified, and remove the diffuseTexture entirely.

Import `VertexBuffer` from `@babylonjs/core`.

Keep `mesh.position` at `center.x, 0, center.z` -- the vertex displacement is relative to the mesh's local space, and since the mesh center is at y=0, the vertex y values ARE the world height. Actually, remove the `0` from mesh.position.y since vertex heights handle elevation.

Do NOT remove `freezeWorldMatrix()` -- terrain chunks don't move after creation, so freezing is fine and improves performance.
