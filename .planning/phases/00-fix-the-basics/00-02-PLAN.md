<task type="auto">
  <name>Task 2: Implement auto-hover on collective release</name>
  <files>apps/game/src/sim/helicopterFlight.ts</files>
  <action>
Modify the `applyHoverAssist` function in `helicopterFlight.ts` to implement altitude-hold when collective input is zero (R/F keys not pressed), regardless of the hover toggle state.

Current behavior: `applyHoverAssist` only runs when `heli.assists.hover === true` (X key toggle) and only dampens lateral drift when collective is 0.3-0.7.

New behavior:
1. Remove the early return `if (!heli.assists.hover) return` -- auto-hover should ALWAYS be active
2. Detect "collective release" state: when `heli.control.collective.raw === 0` (no R/F key pressed), the helicopter should hold its current altitude
3. When collective is released (raw === 0):
   - Read the current velocity Y from `heli.body.linvel()`
   - Calculate the force needed to counter gravity: `mass * 9.81` (get mass via `heli.body.mass()`)
   - Apply an upward force equal to gravity compensation PLUS a proportional correction to kill vertical velocity: `gravityForce + (-velocityY * dampingFactor)`. Use `dampingFactor = mass * 4.0` (strong enough to arrest descent quickly but not oscillate).
   - Apply this via `heli.body.applyForce({ x: 0, y: hoverForce, z: 0 }, true)`
4. When collective IS pressed (raw !== 0), the existing behavior applies (player has manual control of altitude)
5. Keep the existing lateral drift dampening from the old hover toggle as an additional benefit when `heli.assists.hover` is true -- this is the X key toggle behavior. Rename nothing, just modify the logic flow.

Important: Read `heli.control.collective.raw` NOT `heli.control.collective.value` -- we want to detect the raw input state (0 when no key pressed), not the smoothed/processed value.

Check the ControlState type definition to confirm the correct field path for raw collective input. It may be `heli.control.collective` as a number directly, or it may have a `.raw` sub-field. Adjust the implementation to match the actual type.

Also check if the current `applyHoverAssist` has additional logic beyond the toggle guard that should be preserved. Keep any lateral drift dampening or other useful behavior -- just change the altitude-hold trigger from toggle-based to collective-release-based.
